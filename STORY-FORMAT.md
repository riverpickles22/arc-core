# The arc story format

This is the interoperability contract for an **arc story**: what the files
are, which schema each must satisfy, and what the exported graph looks like.
It is written for someone who has never seen arc. The companion document,
[`conventions.md`](conventions.md), is arc's constitution — *how to write a
novel* under this format: canon lifecycle, provenance discipline, prose
binding. You do not need any of that to produce or consume a conforming
story. You need this page.

**A story is files on disk.** No server, no database, no API, and no AI:
nothing in this format requires arc's viewer, arc's backend, Claude, or any
model at all. An implementation conforms by writing YAML and markdown that
two commands accept:

```sh
python3 tools/validate.py      path/to/story    # exit 0 = conforming
python3 tools/export-canon.py  path/to/story    # emits the JSON graph
```

**Conformance is defined by those commands and nothing else**: a conforming
story is one `validate.py` exits 0 on and `export-canon.py` produces a graph
for. There is no registry, no certification, and no ambiguity — if the
validator disagrees with this document, the validator is right and this
document has a bug.

## Format version

`canon/story.yaml` declares the format it is written against:

```yaml
arc_format: 1
```

A bare integer — a story either conforms to a format or it does not. A
consumer that meets a *higher* number than it knows must stop rather than
guess; a missing declaration is warned about, not rejected, so stories that
predate the field still validate (that leniency is itself versioned and can
tighten later).

**Stability:** the canon schemas are `additionalProperties: false`, which
means adding a field is a *breaking* change for existing stories — the
version number moves when fields are added or renamed, vocabularies are
*closed* (widened enums do not break existing stories and do not move it),
or file locations change. Within one `arc_format`, a story that validated
yesterday validates tomorrow.

## Directory layout

The layout is a **convention, not a schema**: `validate.py` checks canon
*content*, not directory shape. What is enforced is enforced by the mapping
table below — a canon file in an unmapped location is a finding.

| path | enforcement | holds |
|---|---|---|
| `canon/story.yaml` | **required** | the manifest: slug, title, logline, status, protagonists, themes |
| `canon/timeline.yaml` | **required** | eras (at least one); every timeref anchors to one |
| `canon/relationships.yaml` | **required** | objective edges; the `relationships:` key may be empty |
| `canon/entities/{characters,places,factions,objects}/*.yaml` | conventional | one entity per file, schema by directory |
| `canon/events/**/*.yaml` | conventional | events, wired by causality |
| `canon/chapters.yaml`, `canon/themes.yaml` | optional | narrative structure; themes with carriers |
| `docs/entities/<type>/<slug>.md` | conventional | one article per entity (`canon:` frontmatter binds it) |
| `docs/style.md`, `docs/vision.md`, `docs/world.md` | optional | the style contract and directional docs |
| `prose/ch-NN/scene-NN.md` | optional | the manuscript; frontmatter binds each scene to canon |
| `annotations/*.yaml` | optional | the author's anchored notes and keypoints |
| `research/`, `material/`, `notes/` | optional | evidence, unplaced material, the author's notebook |
| `locks/*.yaml` | optional | settled prose — validated against `lock` (a paragraph with its quote, a scene alone, or a chapter alone; may carry an absorption link) |
| `assets/`, `view.yaml` | optional | presentation only — never canon, never validated |
| `.arc/` | machine state | gitignored, disposable, nothing but arc reads it |
| `.claude/settings.json` | **never shipped** | per-machine, generated by `hooks/install-hooks.mjs`; copying one between stories copies another machine's absolute paths |

The three **required** files are read unconditionally by `export-canon.py`;
a story without them parses fine and then fails the app reading it, which is
why the validator refuses their absence up front.

## The file-to-schema mapping

Every canon file validates against exactly one schema in `schema/`, selected
by location. This table is executable: `tools/test_story_format.py` parses
it and holds it to `validate.py`'s own mapping, so it cannot drift.

<!-- arc:schema-map — test_story_format.py asserts this table against schema_for() -->

| canon location | schema |
|---|---|
| `canon/story.yaml` | `story` |
| `canon/timeline.yaml` | `timeline` |
| `canon/relationships.yaml` | `relationship` |
| `canon/chapters.yaml` | `chapters` |
| `canon/themes.yaml` | `themes` |
| `canon/entities/characters/*` | `character` |
| `canon/entities/places/*` | `place` |
| `canon/entities/factions/*` | `faction` |
| `canon/entities/objects/*` | `object` |
| `canon/events/**` | `event` |

Outside `canon/`: `annotations/*.yaml` validate against `annotation`,
`locks/*.yaml` against `lock`, and prose scene *frontmatter* against
`scene`. `common.schema.json` holds shared definitions (dates, ids, status)
and maps to no file.

## Vocabularies: which are closed today

Closed enums (a value outside them is a finding — [A35 widens these]):

- `place.kind`: country, region, city, district, street, building, landmark, waterfront
- `event.scope`: story, historical, both
- `faction.kind`: faction, organization, government, movement, pack, family
- `status` (canon lifecycle): proposed, canon

Open (any string): `relationship.kind`, `character.species`, tags, motifs.

Coordinates are real-Earth bounded (lat ±90, lon ±180) today; a fictional
grid cannot yet declare its own system — also A35's to widen.

## The export shape

`export-canon.py` emits one JSON graph — the contract between canon and any
app, including arc's own viewer (it is what `GET /api/canon` serves):

```json
{
  "story": {},
  "timeline": {},
  "entities": {},
  "events": {},
  "relationships": [],
  "themes": [],
  "generated_from": "<story>/canon"
}
```

`entities` and `events` are keyed by id (`char.nell`, `event.the-wreck`);
`relationships` and `themes` are arrays. Every object carries its YAML
fields verbatim — the export is a merge, not a transformation.

## A minimum viable story

Small enough to read whole, produced by `tools/new-story.py` from four
answers (title, logline, period, one protagonist) — and exactly what a
conforming implementation must be able to write by hand:

```
the-thin-story/
├── canon/
│   ├── story.yaml            arc_format, slug, title, logline,
│   │                         status, protagonists, themes: []
│   ├── timeline.yaml         one era with a dated span
│   ├── relationships.yaml    relationships: []
│   └── entities/characters/nell.yaml
│                             id, type, name, species, status,
│                             summary, one state anchored in the era
└── docs/entities/characters/nell.md
                              canon: char.nell frontmatter + an Overview
```

The docs article is load-bearing: the article-coverage rule flags an entity
with no article, and arc's backend refuses to serve a story with findings.

## What the worked example does not exercise

`examples/example-story` currently exercises **7 of the 13 file-backed
schemas**: story, timeline, chapters, character, place, event, relationship.
Not yet exercised there: `annotation`, `faction`, `material`, `object`,
`scene`, `themes` — tracked here so the gap is a fact rather than a memory.
(The negative-test suites under `tools/test_*.py` cover several of these
directly; the example remains the copyable shape.)
